# Smart Road

Симуляция автономного **умного перекрёстка без светофоров** на Rust/SDL2. Машины движутся по отдельным полосам для поворота направо, движения прямо и поворота налево, а центральный контроллер согласует конфликтующие траектории через управление скоростью, безопасную дистанцию и систему резервирования.

## 🚀 Быстрый старт

### Требования

- Rust `1.87+`
- Cargo
- CMake
- C/C++ toolchain
- Windows: MSVC / Visual Studio Build Tools

SDL2 собирается через Rust-зависимость с feature-флагами `bundled` и `static-link`, поэтому отдельная установка SDL2 не требуется.

### Клонирование

```bash
git clone https://github.com/legion2440/smart-road.git
cd smart-road
```

### Запуск

```bash
cargo run
```

Первая сборка занимает больше времени, потому что bundled SDL2 компилируется вместе с проектом.

### Release-сборка

```bash
cargo build --release
```

Оптимизированный бинарный файл создаётся в `target/release/`.

## 📝 О проекте

Симуляция моделирует четырёхсторонний перекрёсток, где у каждого въездного направления есть три отдельные полосы:

- поворот направо;
- движение прямо;
- поворот налево.

Маршрут назначается автомобилю при создании и больше не меняется. Светофорных фаз нет. При приближении автомобиль попадает в контролируемую зону, запрашивает доступ к перекрёстку и меняет скорость в зависимости от активных резервирований.

Несколько неконфликтующих движений могут проходить перекрёсток одновременно. Конфликтующие траектории остаются вне конфликтной зоны до безопасного допуска. Машины одного и того же движения могут проходить контролируемой колонной, потому что дистанция между ними поддерживается отдельным following-layer.

Физика симуляции работает с фиксированным шагом `60 Hz`. Рендеринг синхронизируется отдельно через SDL2 VSync, если он доступен.

## 🚗 Управление

| Клавиша | Действие |
| --- | --- |
| `↑` | Создать автомобиль, движущийся с юга на север |
| `↓` | Создать автомобиль, движущийся с севера на юг |
| `→` | Создать автомобиль, движущийся с запада на восток |
| `←` | Создать автомобиль, движущийся с востока на запад |
| `R` | Включить / выключить постоянную случайную генерацию |
| `Space` | Пауза / продолжение симуляции |
| `Backspace` | Сброс симуляции |
| `Esc` | Завершить симуляцию и показать итоговую статистику |

Каждый автомобиль, созданный стрелкой, получает один из трёх допустимых маршрутов для выбранного направления. Spawn-проверка запрещает наложение машин и дополнительно требует запас вперёд, достаточный для торможения новой машины с cruise speed даже при самом слабом тормозном профиле.

## 🧠 Алгоритм умного перекрёстка

Контроллер основан на **резервировании движений**, а не на фазах светофора.

1. Автомобиль обнаруживается до физической границы перекрёстка.
2. Направление въезда и неизменяемый маршрут задают одно из 12 возможных движений.
3. Предварительно вычисленная матрица описывает конфликты между разными движениями в центральной зоне.
4. Первый ожидающий автомобиль каждого движения становится кандидатом на резервирование.
5. Кандидаты сортируются по времени ожидания и давлению очереди.
6. Резервирование запрашивается до зоны замедления, поэтому одиночная машина на пустом перекрёстке не тормозит без причины.
7. Кандидат допускается, если его траектория не конфликтует с активным другим движением.
8. Несколько машин одного маршрута могут иметь резервирование одновременно; following-layer сохраняет безопасную дистанцию.
9. После выхода автомобиля из конфликтной зоны резервирование освобождается.

Время ожидания защищает от starvation, а давление очереди повышает приоритет направлений, на которых начинает накапливаться транспорт.

## 🛡️ Модель безопасности

Коллизии и близкие сближения проверяются через **ориентированные ограничивающие прямоугольники (OBB)** и **Separating Axis Theorem (SAT)**, поэтому учитывается реальный угол автомобиля.

Модель безопасности включает:

- положительный safety margin вокруг кузова;
- защищённые точки появления автомобилей с запасом тормозного пути;
- минимальную дистанцию `66 px` между машинами одного движения;
- резервирование конфликтной зоны для пересекающихся траекторий;
- регистрацию close calls;
- отдельный диагностический счётчик реальных коллизий.

`66 px` — не случайное число: это `30 px` длины автомобиля + `14 px` safety gap + `22 px` дополнительного запаса для криволинейного движения. Этот запас не даёт повёрнутым OBB сближаться ниже безопасного расстояния на левом повороте радиусом `40 px`.

Новая машина появляется со скоростью `120 px/s`, поэтому same-lane spawn clearance дополнительно включает `8 px` stopping margin и худший тормозной путь для минимального коэффициента торможения `0.80`. При текущих константах следующая машина того же движения может появиться только после `124 px` прогресса лидера.

В нормальном режиме следующая машина держит дистанцию через ограничение скорости торможением. Position-clamp остаётся только аварийным инвариантом: машина без резервирования не может пересечь stop boundary, а ведомая машина — защищённую границу following distance.

## ⚙️ Модель автомобиля

Каждый автомобиль напрямую хранит:

- `time` — время под управлением алгоритма умного перекрёстка;
- `distance` — пройденное расстояние вдоль маршрута;
- `velocity` — фактическую текущую скорость.

Контроллер использует три основных целевых уровня скорости:

```text
STOP    =   0 px/s
SLOW    =  50 px/s
CRUISE  = 120 px/s
```

Скорость не переключается между ними мгновенно. У каждого автомобиля есть собственные ограничения ускорения и торможения, полученные из стабильных псевдослучайных коэффициентов в диапазоне `0.80..1.25`. Коэффициенты зависят только от ID автомобиля, поэтому машины действительно имеют разные динамические характеристики, но одинаковый тестовый сценарий остаётся воспроизводимым.

Номинальные значения:

```text
ускорение = 100 px/s²
торможение = 180 px/s²
```

Перед stop boundary или более медленным лидером применяется кинематический потолок скорости на основе собственной способности автомобиля тормозить:

```text
v_limit = sqrt(2 × braking × remaining_distance)
```

Дополнительный запас `8 px` позволяет штатному торможению завершиться до аварийного position-guard. Благодаря этому ведомая машина не должна мгновенно «втыкаться» со скорости движения в ноль при образовании очереди.

## 📊 Статистика

Нажатие `Esc` завершает симуляцию и открывает итоговый экран статистики внутри SDL-окна. Обязательные строки выводятся в формулировках задания:

- `Max number of vehicles that passed the intersection`;
- `Max velocity`;
- `Min velocity`;
- `Max time that took a vehicle to pass the intersection`;
- `Min time that took a vehicle to pass the intersection`;
- `Close calls`.

Дополнительно собираются:

- минимальная скорость среди движущихся автомобилей;
- количество созданных автомобилей;
- отклонённые попытки создания;
- пиковое количество автомобилей на дороге;
- реальная максимальная медленная/стоящая очередь на одной полосе;
- консервативный максимум машин на одном подходе к перекрёстку;
- обнаруженные коллизии;
- количество срабатываний аварийных safety-clamp;
- среднее время под smart-control;
- средняя пройденная дистанция.

Во время симуляции боковая панель также показывает live-состояние движения.

## 🧪 Тесты и проверка

Запуск unit-тестов:

```bash
cargo test
```

Набор тестов покрывает:

- корректный вход и выход всех 12 траекторий;
- три разные въездные полосы для каждого направления;
- симметричную матрицу конфликтов без self-conflict;
- безопасную дистанцию при spawn;
- обязательный тормозной запас с cruise speed перед повторным spawn в той же полосе;
- индивидуальные профили ускорения и торможения автомобилей;
- все семь детерминированных визуальных типов машин;
- прохождение одиночной машины через пустой перекрёсток без лишнего замедления;
- детерминированные **180-секундные** random-traffic soak-сценарии на четырёх фиксированных seed, где проверяются `0` collisions, `0` close calls, `0` emergency clamps, реальная очередь меньше `8` и консервативная нагрузка на подход меньше `8`.

Для ручной проверки перед аудитом также стоит оставить `R` включённым минимум на одну минуту и наблюдать `COLLISIONS`, `CLOSE CALLS` и длину очередей на live-панели.

## 🎨 Визуализация

SDL2-рендерер включает:

- четырёхсторонний перекрёсток с тремя въездными полосами для каждого направления;
- smart-road текстуры асфальта и центра перекрёстка из `assets/smart-road-atlas.png`;
- неоновые деревья вдоль обочин вне физической зоны дороги;
- семь визуальных типов машин: EV sedan, sport GT, robo-taxi, transit bus, police interceptor, ambulance и fire engine;
- плавный поворот автомобиля по кривой траектории;
- мигающие левые и правые поворотники, которые динамически рисуются поверх любой поворачивающей машины;
- боковую панель управления и live-статистики;
- отдельный итоговый экран статистики, который непрерывно перерисовывается и гарантированно показывает первый кадр до обработки события закрытия;
- автоматическое логическое масштабирование под доступный размер окна.

Тип машины влияет только на внешний вид: все варианты используют одну и ту же проверенную collision geometry `CAR_LEN` / `CAR_W`, поэтому визуальное разнообразие не меняет safety-инварианты. LiDAR-кольца и любые ассеты светофоров не отрисовываются.

Повороты представлены геометрией маршрута и непрерывным изменением heading автомобиля, поэтому машина реально вращается по ходу манёвра, а не скользит боком.

## 🏗️ Архитектура

```text
                         +------------------+
                         |   keyboard / R   |
                         +---------+--------+
                                   |
                                   v
                         +------------------+
                         |    simulation    |
                         | fixed 60 Hz step |
                         +----+--------+----+
                              |        |
                   +----------+        +-----------+
                   |                               |
                   v                               v
          +------------------+            +------------------+
          | reservation mgr  |            | lane following   |
          | conflict matrix  |            | vehicle physics  |
          +--------+---------+            +---------+--------+
                   |                                |
                   +---------------+----------------+
                                   |
                                   v
                         +------------------+
                         | geometry + OBB   |
                         | conflict checks  |
                         +---------+--------+
                                   |
                         +---------+---------+
                         |                   |
                         v                   v
                  +-------------+     +-------------+
                  | statistics  |     | SDL renderer|
                  +-------------+     +-------------+
```

Основные зоны ответственности:

- `geometry` задаёт неизменяемые траектории, safety-константы и матрицу конфликтов;
- `controller` выдаёт и освобождает резервирования;
- `simulation` управляет fixed-timestep циклом, кинематическим торможением и following;
- `vehicle` хранит движение, индивидуальные характеристики и визуальный тип машины;
- `collision` реализует OBB/SAT геометрию;
- `stats` собирает live- и итоговые метрики;
- `stats_screen` рисует финальный отчёт;
- `render`, `sprites` и `ui_font` отвечают за отображение.

## ⚠️ Примечания

- Стрелки обозначают **направление движения**, а не сторону, с которой визуально появляется автомобиль.
- `R` работает как переключатель: первое нажатие запускает постоянную случайную генерацию, второе останавливает её.
- Цветные статусы боковой панели относятся к состоянию симуляции; светофоров на перекрёстке нет.
- Совместимость bundled SDL2 с CMake 4 задаётся через `.cargo/config.toml`.
- Контроллер — идеализированная модель автономного перекрёстка: предполагаются точные маршруты, без ошибок датчиков и задержек связи.
