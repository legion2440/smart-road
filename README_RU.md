# Smart Road

Симуляция автономного **умного перекрёстка без светофоров** на Rust/SDL2. Машины движутся по отдельным полосам для поворота направо, движения прямо и поворота налево, а центральный контроллер согласует конфликтующие траектории через управление скоростью, безопасную дистанцию и систему резервирования.

## 🚀 Быстрый старт

### Требования

- Rust `1.87+`
- Cargo
- CMake
- C/C++ toolchain
- Windows: MSVC / Visual Studio Build Tools

SDL2 собирается через Rust-зависимость с feature-флагами `bundled` и `static-link`, поэтому отдельная установка SDL2 не требуется.

### Клонирование

```bash
git clone https://github.com/legion2440/smart-road.git
cd smart-road
```

### Запуск

```bash
cargo run
```

Первая сборка занимает больше времени, потому что bundled SDL2 компилируется вместе с проектом.

### Release-сборка

```bash
cargo build --release
```

Оптимизированный бинарный файл находится в:

```text
target/release/smart-road
```

## 📝 О проекте

Симуляция моделирует четырёхсторонний перекрёсток, где у каждого въездного направления есть три отдельные полосы:

- поворот направо;
- движение прямо;
- поворот налево.

Маршрут назначается автомобилю при создании и больше не меняется. Светофорных фаз нет. Вместо них автомобиль при приближении попадает в контролируемую зону, запрашивает доступ к перекрёстку и изменяет скорость в зависимости от текущих резервирований.

Несколько неконфликтующих направлений могут проходить перекрёсток одновременно. Конфликтующие движения удерживаются за границей конфликтной зоны до безопасного допуска.

Физика симуляции работает на детерминированном фиксированном шаге `60 Hz`, а рендеринг синхронизируется отдельно через SDL2 VSync, если он доступен.

## 🚗 Управление

| Клавиша | Действие |
| --- | --- |
| `↑` | Создать автомобиль, движущийся с юга на север |
| `↓` | Создать автомобиль, движущийся с севера на юг |
| `→` | Создать автомобиль, движущийся с запада на восток |
| `←` | Создать автомобиль, движущийся с востока на запад |
| `R` | Включить / выключить постоянную случайную генерацию |
| `Space` | Пауза / продолжение симуляции |
| `Backspace` | Сброс симуляции |
| `Esc` | Выход и показ итоговой статистики |

Каждый автомобиль, созданный стрелкой, получает один из трёх допустимых маршрутов для выбранного направления. Проверка точки появления не позволяет создать новую машину поверх уже существующей.

## 🧠 Алгоритм умного перекрёстка

Контроллер движения основан на **резервировании траекторий**, а не на фазах светофора.

Для каждого автомобиля, входящего в зону smart-control:

1. Автомобиль обнаруживается до физической границы перекрёстка.
2. Неизменяемые направление въезда и маршрут определяют одно из 12 возможных движений.
3. Контроллер проверяет заранее вычисленную матрицу конфликтов между всеми парами движений.
4. Запрашивать резервирование может только первый ожидающий автомобиль каждого движения.
5. Кандидаты сортируются по времени ожидания и давлению очереди.
6. Резервирование выдаётся только в том случае, если траектория не конфликтует ни с одним уже активным движением.
7. Несколько совместимых траекторий могут проходить перекрёсток одновременно.
8. После выхода автомобиля из конфликтной зоны резервирование освобождается.

Время ожидания защищает от starvation, а длина очереди повышает приоритет направлений, на которых начинает накапливаться транспорт.

Контроллер отделён от рендеринга и низкоуровневой физики автомобилей.

## 🛡️ Модель безопасности

Коллизии и близкие сближения проверяются через **ориентированные ограничивающие прямоугольники (OBB)** и **Separating Axis Theorem (SAT)**. Поэтому учитывается реальный угол автомобиля, а не только axis-aligned прямоугольник.

Модель безопасности включает:

- положительный safety margin вокруг кузова;
- защищённые точки появления автомобилей;
- минимальную дистанцию между машинами одного движения;
- резервирование конфликтной зоны для пересекающихся траекторий;
- регистрацию close calls;
- отдельный диагностический счётчик реальных коллизий.

Автомобили одной полосы сортируются по прогрессу вдоль маршрута. Следующая машина не может продвинуться ближе заданной безопасной дистанции к ведущей.

## ⚙️ Модель автомобиля

Каждый автомобиль напрямую хранит требуемое состояние движения:

- `time` — время под управлением алгоритма умного перекрёстка;
- `distance` — пройденное расстояние вдоль маршрута;
- `velocity` — фактическая текущая скорость.

Контроллер использует три основных целевых уровня скорости:

```text
STOP    =   0 px/s
SLOW    =  50 px/s
CRUISE  = 120 px/s
```

Скорость не переключается между ними мгновенно. Автомобили используют ограниченное ускорение и торможение:

```text
максимальное ускорение = 100 px/s²
максимальное торможение = 180 px/s²
```

Если движение заблокировано, автомобиль заранее замедляется перед границей резервирования и при необходимости полностью останавливается. После получения доступа он снова разгоняется до cruise speed.

## 📊 Статистика

При нажатии `Esc` открывается окно итоговой статистики.

Основные показатели:

- количество автомобилей, прошедших перекрёсток;
- максимальная скорость;
- минимальная скорость;
- максимальное время прохождения;
- минимальное время прохождения;
- close calls.

Дополнительно собираются:

- количество созданных автомобилей;
- отклонённые попытки создания;
- пиковое количество автомобилей на дороге;
- максимальная очередь на одной полосе;
- обнаруженные коллизии;
- среднее время под smart-control;
- средняя пройденная дистанция.

Во время симуляции боковая панель также показывает текущее состояние движения и основные live-метрики.

## 🎨 Визуализация

SDL2-рендерер включает:

- четырёхсторонний перекрёсток с тремя въездными полосами для каждого направления;
- плавный поворот автомобиля по кривой траектории;
- автомобильные спрайты;
- мигающие левые и правые поворотники;
- боковую панель управления и live-статистики;
- автоматическое логическое масштабирование при изменении физического размера окна.

Повороты представлены геометрией маршрута и непрерывным изменением heading автомобиля, поэтому машина реально вращается по ходу манёвра, а не скользит боком.

## 🏗️ Архитектура

```text
                         +------------------+
                         |   keyboard / R   |
                         +---------+--------+
                                   |
                                   v
                         +------------------+
                         |    simulation    |
                         | fixed 60 Hz step |
                         +----+--------+----+
                              |        |
                   +----------+        +-----------+
                   |                               |
                   v                               v
          +------------------+            +------------------+
          | intersection     |            | lane following   |
          | reservation mgr  |            | + vehicle physics|
          +--------+---------+            +---------+--------+
                   |                                |
                   +---------------+----------------+
                                   |
                                   v
                         +------------------+
                         | geometry + OBB   |
                         | conflict checks  |
                         +---------+--------+
                                   |
                         +---------+---------+
                         |                   |
                         v                   v
                  +-------------+     +-------------+
                  | statistics  |     | SDL renderer|
                  +-------------+     +-------------+
```

Основные зоны ответственности разделены по модулям:

- `geometry` задаёт неизменяемые траектории и матрицу конфликтов;
- `controller` выдаёт и освобождает резервирования перекрёстка;
- `simulation` управляет fixed-timestep циклом и продольным движением машин;
- `collision` реализует OBB/SAT геометрию;
- `stats` собирает итоговые и live-метрики;
- `render` и `sprites` отвечают только за отображение.

## ⚠️ Примечания

- Стрелки обозначают **направление движения**, а не сторону, с которой визуально появляется автомобиль.
- `R` работает как переключатель: первое нажатие запускает постоянную случайную генерацию, второе останавливает её.
- Цветные статусы на боковой панели относятся к состоянию симуляции; светофоров на перекрёстке нет.
- Проект использует фиксированную логическую область рендеринга и масштабирует её под доступный размер окна.
- Совместимость bundled SDL2 с CMake 4 задаётся через `.cargo/config.toml`.
